## 一句话概括

无标签 RLVR（拿多数投票当奖励）训久了会崩，而且只在题目多时才崩。本文把这种现象解释为：题目共享模型参数，共享方向出现了"集体失稳"。论文还给出了临界题目数的估算公式。

## 核心方法

- 先看单题：模型对答案还拿不准时，自我强化会把一个很小的共同扰动越放越大；模型已经有把握时，扰动会自动衰减。
- 再看多题：有些参数会把所有题的答案往同一方向推，比如统一的格式或偏好答案。这类参数能同时收到每道题的多数投票信号，增长速度和题目数 N 无关；每道题自己的"锐化"却会随 N 增大而变慢。两者赛跑，就得到临界规模 N_c：耦合越强、初始越不自信，N_c 越小。
- 在核函数（NTK）版本的理论里，作者还找到一种起保护作用的耦合（锐化效果在题目之间泛化），并提出一个批级边际熵奖励，用来压住"所有题给同一答案"这种模式。

## 关键结果

- 仿真结果符合理论：崩溃前后是陡峭的相变，N_c 约与耦合强度的平方成反比，batch size 只有对数级影响，初始就自信的模型不会崩。换成 GRPO、更大的组、Adam 等设置，规律依然成立。
- 小 Transformer 实验：去掉共享方向后完全不崩，加回来又会崩；训练集越大、基座模型熵越高，崩得越厉害。
- 局限：边际熵奖励只是把失稳转移到下一个集体模式，准确率仍然保不住。用初始核做预测能给崩溃风险排序，但校准很差。

## 为什么值得关注

这是第一个从机制上解释"数据越多越容易崩"的工作，而且给出了可以检验的定量判据。对做无标签或自奖励 RL 的人来说，它指出了真正该盯的风险：跨题共享方向和基座模型的不确定度。单纯调 batch size 或加熵正则，都解决不了根本问题。
