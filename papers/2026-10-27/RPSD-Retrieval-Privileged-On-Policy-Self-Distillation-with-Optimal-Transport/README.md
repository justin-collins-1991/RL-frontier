## 一句话概括

在基于 LLM 的生成式序列推荐中，RPSD 把 GRPO 的序列级奖励改写成 token 级信用，并检索相似用户的行为轨迹作为教师的"特权信息"，同时解决"奖励不分 token"和"只看单个用户"两个问题。

## 核心方法

- **同策略自蒸馏（OPSD）**：同一个模型分饰两角。学生只看普通推荐 prompt 生成回答；教师额外拿到特权信息，对学生这条回答逐 token 重新打分（不重新生成）。两者在每个 token 上的置信度差异转成权重，与 GRPO 的组内归一化优势按比例混合，得到 token 级优势，让真正决定推荐哪个物品的 token 拿到更多信用。
- **检索式特权信息**：普通 OPSD 只把真实标签给教师，只能告诉它"哪个对"，说不清"为什么对"。RPSD 先粗检索候选用户，再用考虑时间结构的最优传输（OT）对齐交互轨迹（同时看物品相似度和时间顺序、近期加权），并通过多样性筛选保留互补的轨迹；这些相似用户的后续行为加上真实物品，一起作为教师的上下文。
- 特权信息只在训练时使用，推理时仍只有学生 prompt，部署零额外开销。

## 关键结果

- 在三个真实推荐数据集上取得 SOTA，稳定优于 Rank-GRPO、RecZero 等 RL 基线。
- 和 GRPO 相比训练奖励更高、token 熵变化更健康；消融显示，去掉 OT 检索、只用真实标签作特权信息时效果明显下降，说明跨用户证据确实有用。

## 为什么值得关注

这是首个把 OPSD 引入序列推荐、并用跨用户行为作为特权信号的工作。它给出了一个通用思路：特权教师的质量取决于特权信息够不够丰富，只喂标签容易让教师"走捷径"；换成检索来的结构化证据，就能在不改推理流程的前提下产出更密的监督信号。这一思路可以迁移到其他奖励稀疏的 RL 后训练场景。
