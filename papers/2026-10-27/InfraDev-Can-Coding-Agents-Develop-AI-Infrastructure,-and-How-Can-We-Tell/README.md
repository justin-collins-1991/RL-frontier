## 一句话概括

InfraDev 是一个测编码智能体能否开发大模型训练、推理和 RL 基础设施的基准。最强模型也只解决了 38.9% 的任务，而原有测试会大量误判。

## 核心方法

- **任务来源**：从 Megatron-LM、vLLM、verl 两万多个已合并 PR 中，筛出 36 个改动核心功能、超过千行的 PR，让智能体在 PR 合并前的代码上重新实现。平均每个任务改 17 个文件，20 个需要多卡运行。
- **测试和 prompt 一起生成**：原 PR 的测试很弱。24 个任务完全不校验数值，15 个性能优化里有 13 个不检查是否真的省了资源。作者让一个 agent 先写"能过官方测试但实际没做对"的对抗补丁，再写能拦住它们的隐藏探针（hidden probes）。探针必须放过官方补丁，同时拒掉原始代码、对抗补丁和只有接口没有实现的空壳补丁。之后再生成 prompt，写清探针会调用的所有接口，但不透露实现方法。
- **共享执行环境**：各任务复用依赖和模型权重缓存，存储减少 52–57%，构建时间缩短 13–14%。

## 关键结果

- 六个前沿模型里最好的只解决了 38.9%。
- 通过全部官方测试的提交中，有 32% 被探针拒掉。如果直接用原 PR 描述当 prompt，没有一个模型能解决任何任务。
- 失败主要是结构错误和状态错误。智能体给自己写的测试很少检查显存、耗时和通信量。
- 把这些失败模式整理成 agent skill 后，GPT-5.6 Sol 在 Megatron-LM 任务上的解决率从 42.1% 升到 52.6%。

## 为什么值得关注

RL 训练框架（如 verl）越来越多地由 agent 参与开发，而"测试通过"不等于"做对了"。这篇论文给出了一套更可信的评测方法：用对抗补丁找出漏测的需求，用探针把它们补上。这个思路对 RLVR 中奖励被钻空子的问题也有参考价值。
