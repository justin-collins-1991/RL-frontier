## 一句话概括

多任务、多奖励的 LLM 强化学习里，长度这类辅助奖励会打乱主奖励（如答对与否）定下的好坏顺序。CONCUR 改的是优势估计：对辅助奖励的分数做修正，让它和主奖励的排序保持一致。

## 核心方法

很多辅助奖励受主奖励“门控”：回答错了，辅助分就不能高过主分。但 GRPO 这类组内相对优势估计把它当成普通分量来标准化，结果辅助分可能把主奖励的排序翻过来。而且一组回答都拿到主奖励满分时，排序就只剩辅助奖励说了算。CONCUR 把每个门控辅助奖励的标准化分数换成满足两条约束、又离原值最近的一组分数：（1）主奖励更高的回答，辅助分不能更低；（2）主奖励满分的回答，辅助分一律相等。CONCUR-T 在整个训练中都执行这两条。CONCUR-A 会检查辅助奖励的表现：如果在通过的回答里，它顺着主奖励排序的次数多于反着排的次数，就对它放开第二条。

## 关键结果

实验覆盖两个模型家族的三个模型，任务包括数学、代码、指令遵循和写作。两个变体的平均分都高于所有基线，也高于把门控辅助奖励全部去掉的做法。可见“保留辅助奖励伤一些任务，去掉又伤另一些任务”的两难被缓解了。（基于摘要）

## 为什么值得关注

多奖励 RL 后训练已经很常见，长度、格式等辅助奖励带偏主目标是大家都会踩的坑。CONCUR 只改优势估计这一步，不用重新设计奖励，也不用手调权重，接到现有 GRPO 类流程里比较容易，对做多任务混合训练的团队有直接参考价值。
