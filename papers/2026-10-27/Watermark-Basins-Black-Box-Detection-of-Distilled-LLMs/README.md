## 一句话概括

学生模型用带水印的教师输出做蒸馏后，参数空间里会留下一个跟水印密钥绑定、和普通任务方向正交的“水印盆地”。WM-Basin 只调用可疑模型的 API，就能借这个信号判断它是否偷偷蒸馏过。

## 核心方法

- **发现**：在白盒实验里，同一基座分别用带水印和不带水印的教师轨迹微调。两者的权重差可以拆成一条宽阔的“任务方向”和一条微弱、但只属于某个密钥的“水印方向”，后者很难被后续训练抹掉。
- **检测**：拿一个固定的干净探针模型，把可疑模型生成的文本反传成梯度；先投影掉共享的任务子空间，再比较剩下的残差梯度和各密钥参考梯度的对齐程度。
- **统计**：把真密钥放进一批诱饵密钥里排名，用排名检验给出精确可控的 p 值。

## 关键结果

- 实验覆盖 1200 个学生模型（135M–8.2B）、4 个教师、4 种水印方案，任务是数学推理蒸馏。
- 在 0.1% 误报率下，n-gram=1 时检出率 79%，n-gram=3 时 45%；token 级 SOTA 基线分别只有 29% 和 1.3%。
- 学生模型经过量化、剪枝、RL 后训练，检测效果基本不受影响；用干净数据持续 SFT 会削弱黑盒检测。

## 为什么值得关注

API 蒸馏已经是闭源推理模型面临的主要威胁。教师用低温采样时，token 级统计方法基本会失效。这篇工作把检测从 token 空间搬到了参数（梯度）空间：不需要可疑模型的权重或 logits，误报率有严格保证，也能扛住常见的后处理。对模型厂商取证和第三方审计都很实用，也给“输出水印能否作为蒸馏证据”提供了更可靠的技术路径。
