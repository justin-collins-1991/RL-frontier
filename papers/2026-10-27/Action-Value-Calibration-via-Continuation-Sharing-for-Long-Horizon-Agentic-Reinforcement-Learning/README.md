## 一句话概括

ConCal 把同一批 rollout 里"走到相同局面"的多条轨迹的后续结果拿来互相参考，校准每个动作的价值估计，让长程 LLM 智能体的步级信用分配更准，而且不需要额外采样。

## 核心方法

GiGPO 会在相同状态下比较不同动作，但每个动作的价值只看它自己那一条轨迹的后续回报：好动作后面一步走错，也会被判成坏动作。ConCal 的做法是：

- **匹配访问**：在同一任务的轨迹中，把"上一状态、执行动作、当前状态"都相同的访问点归为一组，它们的后续经验可以共享。
- **部分共享**：每个访问点的后续价值 = 自己这条轨迹的估计与组内均值的加权混合，组越大越倾向均值，但保留个体差异，而不是简单取平均。
- **递归回传**：校准后的价值沿轨迹逐步往前传，让更早的动作也能用上其他轨迹的证据。
- 最后用"即时奖励 + 实际后继状态的校准价值"作为动作价值，照常在状态组内算相对优势，与 episode 级优势合并后做 PPO 更新。

## 关键结果

- 基于 Qwen2.5-1.5B-Instruct，成功率相比 GiGPO 在 ALFWorld 上提升 3.39 个百分点，在 WebShop 上提升 5.86 个百分点，平均成功率也高于 GraphGPO。
- 诊断实验显示：信用冲突率（同一决策既拿正分又拿负分的比例）明显下降，组内相对价值误差降低 42%~51%，动作排序与参考结果更一致。
- 消融实验表明，递归共享和保留个体估计两部分都有贡献。

## 为什么值得关注

长程智能体 RL 的关键难点是信用分配。ConCal 不训练 critic，也不增加采样，只是更充分地利用 batch 里已有的轨迹信息，可以直接接在 GRPO/GiGPO 类方法上。它指出了一个常被忽视的问题：状态分组决定"拿谁比"，价值估计决定"比什么"，后者同样需要降噪，对做 agentic RL 的工程实践有直接参考价值。
