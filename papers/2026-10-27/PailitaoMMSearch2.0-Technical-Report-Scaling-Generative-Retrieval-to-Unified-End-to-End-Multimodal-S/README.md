## 一句话概括

淘宝拍立淘用一个原生多模态大模型，输入"一张图 + 一句自由描述"，直接生成商品的 Semantic ID 完成检索。找同款、改属性、找搭配都交给这一个模型，不需要再做意图路由。

## 核心方法

- **问题**：工业界的生成式检索往往和具体场景绑死，体现在三处：训练数据只来自现有入口的日志，一个模型只服务一种检索关系，模型大小和推理预算只针对一种延迟要求调过。
- **数据扩展**：做了一套可组合的数据工具（粗筛/精筛、生成查询文本、标注 CoT、质检），按意图和阶段拼成不同流程。新意图没有流量时靠合成数据冷启动，上线后再用真实流量清洗、迭代，之后持续产出数据。
- **意图扩展**：基于 Qwen3.5 VLM 分三步训练。先做继续预训练（CPT），让模型学会商品知识和 SID 词表；再做多意图、多思考预算混合的 SFT（不思考/少思考/多思考）；最后用统一 RL 联合优化各类意图，加入意图均衡采样，并采用 Sample–Beam rollout：推理过程用采样，SID 用 beam 解码，跟线上一次返回多个候选的方式保持一致。
- **场景扩展**：模型规模（0.8B/2B/4B）和思考预算组合出不同的质量/成本档位，按各场景的延迟和显存约束选一档。

## 关键结果

- 相比 SFT，Sample–Beam RL 把宏平均优秀率提高了 5.97 个点。
- 已在淘宝拍立淘上线。线上 A/B 显著提升：商品浏览 +17.90%，成交笔数 +27.04%，GMV +8.94%。

## 为什么值得关注

这篇论文给出了一套比较完整的工业方案：数据怎么合成、训练分哪几个阶段、怎么部署上线，都有交代。从 RL 的角度看，Sample–Beam rollout 值得借鉴。模型的"动作"其实是一组 beam 候选，rollout 方式就跟着线上的多候选服务来设计，训练和线上服务因此更一致。这个思路可以推广到其他生成式推荐/检索场景。
