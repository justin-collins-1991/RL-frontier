## 一句话概括

MASCAL 用强化学习让每个 agent 在给出答案的同时输出一个“答对概率”，上游把这个概率交给下游，下游据此决定是直接采信还是再去检索核实。

## 核心方法

- **任务与置信度联合训练**：在 GRPO 框架下，每条 rollout 分成“任务段”和“置信度段”。任务段按正确率优化，置信度段额外加一个校准损失，让模型报出的概率和真实正确率对得上。
- **置信度随报告传递**：上游的报告里除了答案和证据，还附上这个概率。下游直接拿上游真实生成的报告来训练，最终答案同样带一个校准过的概率。
- **置信度感知加权**：把上游置信度遮掉后对比下游各 token 的输出变化，变化越大的位置说明越依赖这个信号，训练时就给这些位置更高的权重，引导下游学会真正用上这个信号。

## 关键结果

- 在顺序交接、报告融合、答案复审三种协作架构上测试，覆盖 Web 多跳问答、逻辑推理和数学推理。准确率高于单 agent、不传置信度的多 agent 系统以及已有的基于置信度的方法，上下游的校准质量也都有提升。
- 干预实验证实，改变上游置信度确实会改变下游的行为。
- 在两跳架构上训练的模型可以直接迁移到更深的检索链，换成更小的模型同样有效。
- 最终置信度可以用来做选择性作答和定向复查，明显降低交付结果的错误率。

## 为什么值得关注

多 agent 系统的一个常见薄弱环节是交接：下游只能看文字证据，凭感觉判断上游说得对不对。MASCAL 把“这个答案有多可靠”变成一个可学习、可传递的数字，把置信度的产生、传递和使用放进同一套 RL 训练里。工程上，这个信号可以直接拿来设拒答阈值、把复查算力花在最需要的地方，是让 agent 流水线更可控的一个实用方案。
