## 一句话概括

CodeSpecWeave 批量合成“需求彼此牵制”的编码任务，既用来做强化学习训练，也用来评测编码智能体。

## 核心方法

作者发现，只堆需求数量没用：模型逐条满足就能过，任务退化成清单。关键是让需求相互耦合，一个设计选择会限制其他选择，比如输入校验、事务回滚和向后兼容必须一起考虑。

流程分两步。合成阶段，以从真实提交、issue 和 PR 中挖掘的需求种子为参照，由智能体探索代码库，迭代生成任务描述和可执行测试。校验阶段，让多个模型试做，再由审查智能体检查解题轨迹和补丁，找出放过错误实现或误杀合理实现的测试，并按难度筛选、修复后复验。

## 关键结果

- 训练集含 4,670 个任务，覆盖 2,865 个仓库；每个任务平均 8.36 条需求、4.08 类行为，明显高于现有数据集。
- 在这些任务上做强化学习后，DeepSWE-v1.1 成绩相比基座模型显著提升，并大幅领先现有基线。
- 审查中约 74% 的任务暴露出测试问题，说明自动生成的测试不能直接信任。
- CodeSpecWeave-Bench 含 100 个任务、1,044 条需求，能清楚区分前沿模型，且各模型仍有很大提升空间。

## 为什么值得关注

编码智能体的强化学习训练，瓶颈正从模型转向任务和验证器的质量。这篇工作说明，需求之间的耦合比数量更重要，并给出了可规模化的造题与验题流程，对构建训练环境和评测集都有参考价值。
