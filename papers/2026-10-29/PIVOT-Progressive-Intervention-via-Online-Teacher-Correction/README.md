## 一句话概括

在 RLVR 训练中，让强教师模型在学生推理出错的地方插入一段纠正，学生接着往下写；同时对这段纠正加 token 级 KL 监督。这样一来，难题上整组 rollout 全错、拿不到奖励信号的问题就有了解法。

## 核心方法

作者把教师引导拆成两类：**轨迹级干预**（让学生能接触到能拿奖励的推理路径）和 **token 级监督**（给出逐 token 的稠密学习目标）。实验发现，这两类单独用都不够：
- 只给教师前缀（如 POPE），学生学会的是"从别人的前缀往下接"，自己却生成不出那些关键决策，换成 oracle 前缀也几乎没提升；
- 只在学生自己的轨迹上做蒸馏（如 KDRL），学生一旦早期出错，教师会在"回头纠错"和"顺着错路继续"之间摇摆，监督目标互相冲突。

PIVOT 把两者合在一起：在 GRPO 的 rollout 组里加入"教师辅助轨迹"，即学生先写前缀，教师给出纠正片段，学生再继续生成。整条轨迹由验证器奖励（GRPO）优化，教师写的片段再额外加教师-学生 KL 损失。此外，论文还系统分析了在哪里干预、用哪种 KL、引导给多少，总结出一套可直接复用的做法。

## 关键结果

- SynLogic 难逻辑游戏上，平均 avg@8 从最强基线的 19.5% 提升到 35.6%，接近翻倍；
- 数学推理任务中，PIVOT 在分布内和分布外基准上都稳定超过各基线。

## 为什么值得关注

RLVR 常被认为只能放大基座模型已有的能力，遇到难题基本学不动。PIVOT 讲清了一点：教师信号不仅要能把学生带到正确答案，还要让学生学得会。纠正片段建立在学生自己的前缀上，和学生的分布接近，教师给出的目标也更明确，不再左右摇摆。对于想用强模型带小模型攻克难推理任务的团队，这是一套实用的训练方案。
