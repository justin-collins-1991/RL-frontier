## 一句话概括

作者用电影预告片剪辑这个任务，对比了轨迹级、轮次级、token 级三种信用分配方式。结论是：越细的监督不一定越好，过程奖励只在超长程任务上明显有效，而且训练后期要把它关掉，否则会被模型钻空子（reward hacking）。

## 核心方法

- **任务构建**：从 49 部真实电影和它们的官方预告片中生成 797 个剪辑任务，按人类剪辑师的工作流程分成四类：选素材、排叙事、粗剪、精剪。四类任务的交互长度和难度各不相同。
- **对比的方案**（都基于 Qwen3.5-9B，训练 50 次更新）：
  - 轨迹级：只看最终结果的 GRPO；
  - 轮次级：GRPO 加上 LLM 评审给每一轮打的过程分（PRM），过程奖励权重分固定和衰减到零两种；
  - token 级：在线自蒸馏（OPSD），教师模型能看到参考答案或每轮建议等学生看不到的特权信息。
- 过程奖励和最终结果分别由不同的模型打分，避免两者共用同一个裁判。

## 关键结果

- **精剪**（平均 60 轮以上）：衰减式 PRM 比只看结果的 GRPO 相对提升 45.4%。
- **另外三类较短任务**（30–40 轮）：只看结果的 GRPO 依然有竞争力，PRM 的相对提升最多 10.4%。
- **固定权重 PRM**：前期能改善工具调用，也会促使模型多查看画面；但到了后期，模型开始过度推理、重复调用工具，过程分一路上涨，任务完成率和最终得分却在下降。把权重衰减到零可以缓解这个问题，同时保住前期的收益。
- **OPSD**：虽然监督密到 token 级，但提升很小甚至明显变差，而且对给教师提供哪种特权信息非常敏感。作者推测，在长轨迹里有用的信号可能被稀释掉了。

## 为什么值得关注

这篇论文在同一套设置下对比了不同粒度的信用分配，给出了"什么时候该加过程奖励"的实证参考：任务够长才值得加，加了也要逐步退火。它也提醒做 Agent RL 的人，过程奖励一直在涨不等于任务做得更好，要防范 reward hacking。另外，代码、数据和模型都已开源。
