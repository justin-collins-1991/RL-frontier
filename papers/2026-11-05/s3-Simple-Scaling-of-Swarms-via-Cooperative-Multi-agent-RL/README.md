## 一句话概括

不预设 leader、角色或轮次，只给 LLM 智能体"发消息/读消息"两个工具和一个团队奖励，用多智能体 RL 让它们自己学会何时单干、何时分享、怎么分工。

## 核心方法

- **同一模型的 N 个副本**各自处理一份任务，互相看不到推理和工具结果，只能通过 `message` / `read_messages` 主动沟通；队友名字每局随机打乱，防止学到固定约定。
- **异步执行**：生成按最多 1024 token 切片，消息以通知形式插入，慢的智能体不会拖住整个团队，发现能及时被队友用上。
- **团队奖励 + 组相对 RL**：只要有一人答对，全队得分，并扣除总 token 开销；同题多次团队采样做归一化，所有 token 共享团队优势，所以"帮队友成功"也会被强化。
- 严格对齐训练和推理预算，与 best-of-N 单智能体对比。

## 关键结果

- 信息聚合任务：用 4 人训练、8 人测试，解题数是最强基线的 25 倍以上。
- 并行探索任务：重复劳动减少近 50%，比 best-of-N 最多高 9.4 个百分点。
- 改成个人奖励会形成社会困境、合作崩溃；关掉通信或只做 SFT 也明显变差，说明增益来自学到的协作。
- 智能体会自发采用不同策略，并出现互补的角色。

## 为什么值得关注

现在的多智能体系统大多靠人手工设计编排框架。这篇工作在预算对齐、且以 best-of-N 为基线的严格设置下，证明了协作组织可以从 RL 中学出来，还能外推到更大的团队。这为"用更多模型扩展推理"提供了一条不依赖人工设计 harness 的路线。
