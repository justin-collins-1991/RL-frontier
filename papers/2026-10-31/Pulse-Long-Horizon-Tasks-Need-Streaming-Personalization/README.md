## 一句话概括

让一个独立的轻量记忆智能体在长程任务执行过程中持续"旁听"，在合适的时机把用户偏好和项目约束送到主智能体手里，而不是只在请求开头检索一次记忆。

## 核心方法

- **问题**：现有记忆增强方法基本只用初始请求去检索记忆。可很多偏好要等执行到某一步（比如已经选好了某家酒店）才真正派上用场，结果智能体经常漏掉约束，最后还得用户自己提醒。
- **两类长期记忆**：用户 Topic 图记录跨任务的偏好；项目记忆保存可复用的工作流和当前项目状态。
- **流式旁路监听**：记忆智能体先用记忆补全初始请求，之后逐条观察消息、候选工具调用和工具结果。出现新实体或新子目标时，由检索门控决定要不要检索，然后从三种动作里选一个：保持沉默、非阻塞地补充信息、在工具调用提交前拦截并要求重新规划。
- **RL 训练**：用 GRPO 训练 Qwen3-8B 记忆策略。动作选对奖励 +1，错误拦截 -1，其他错误 0，专门压低误打断，避免无谓的重新规划。

## 关键结果

- π-Bench 得分 71.9%，MCP-Persona 得分 46.4%，两个数据集的总分都是所比方法中最高的。
- 记忆使用更高效，任务执行也更快：主智能体不用自己反复检索、核对约束，推理轮数和上下文负担都减少了。

## 为什么值得关注

- 把个性化从"一次检索"变成"跟随执行状态持续供给"，正好对上 Agent 长程任务里偏好要到中途才起作用的问题。
- 记忆和任务执行解耦，小模型就能当旁路监督，可以插到已有 Agent 上用，不用改主模型。
- 用 RL 学"什么时候插话"，这个思路可以推广到安全护栏、合规检查这类在线干预场景。
