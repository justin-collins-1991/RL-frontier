## 一句话概括

把网页智能体拆成"任务分解器 + 执行器"两个独立的 7B 模型，用分层 GRPO 让两者在同一批交互数据上同时做 RL，在长程网页任务上明显超过更大的单体模型。

## 核心方法

- **造规划数据**：现有 GUI 轨迹数据集只有动作，没有子任务标注。作者让 GPT-5.2-Codex 读 ScaleCUA 的完整轨迹（截图加动作），反推出有序子任务列表，得到约 7.6 万条分解样本。
- **两阶段 SFT**：基于 Qwen2.5-VL-7B 分别微调分解器（输入指令和首屏截图，输出子任务）和执行器（基于子任务、当前截图和历史动作输出下一步操作）。
- **分层联合 RL**：分解器为每个任务采样 K 份计划，执行器对每份计划各跑 M 次完整 rollout。执行器的优势在同一计划内的多次执行之间比较；分解器的优势按各计划的平均成功率在计划之间比较。两个模型用同一批数据同步更新，只用最终成败奖励，不需要过程奖励。

## 关键结果

- 在 WebArena-Lite-v2 上，JHiMA-WebRL-14B（7B 分解器加 7B 执行器）的平均成功率为 37.2%。在相同训练任务和评测协议下做过 RL 的 ScaleCUA-32B 只有 24.0%。
- 消融实验表明：RL 阶段同时更新分解器，比冻结分解器、只训执行器效果更好。

## 为什么值得关注

以往的规划器/执行器方案要么冻结其中一方，要么分开或交替训练。这篇工作首次在网页环境中，用同一批 rollout 同时训练两个独立参数的模型，让计划能按执行器的实际能力调整。做法简单：只扩展了 GRPO 的分组方式，也不需要稠密奖励。它说明在长程智能体任务上，"角色拆分加联合训练"可以用更小的模型替代单纯扩大参数规模，工程上容易复用。
