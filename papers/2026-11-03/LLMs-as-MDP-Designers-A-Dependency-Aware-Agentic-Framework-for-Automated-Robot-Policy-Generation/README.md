## 一句话概括

LLM 不在运行时直接做决策，而是在部署前充当“RL 工程师”：从一段自然语言任务描述出发，自动完成 MDP 建模、仿真环境实现和策略训练，最终产出一个不依赖 LLM、可以独立运行的机器人策略。

## 核心方法

作者观察到，人类专家搭建机器人 RL 的过程可以拆成两个阶段，而且两者结构不同：

- **建模阶段有先后依赖**：参数、变量、约束、奖励、终止条件要按顺序确定，前面的错误会一路传到后面；
- **实现阶段是模块化的**：MDP 定好之后，场景、动作、观测、奖励等配置模块大多可以分开生成。

ARPG 按这个结构设计多智能体流程：建模阶段按顺序逐步生成，每一步做局部校验，出错时只修改对应环节，避免“修好一处、又弄坏另一处”的错误回流；实现阶段按 Isaac Lab 的模块结构分别生成代码。所有中间产物都以人类可读的形式保存下来，专家可以检查、修改并只重跑局部。方法重点要解决的问题是：代码能跑，但状态、动作、奖励、终止条件之间语义不一致，导致策略根本学不起来。

## 关键结果

在 Isaac Sim 的机械臂操作和足式运动任务上，与单次生成的 LLM 基线及现成的智能体系统相比，ARPG 在建模正确率、环境可执行率和最终策略生成成功率上都更好。在自定义机器人、标准 RL 环境和工程领域 MDP 上的补充演示表明，同一套建模流程也能用在主基准之外。

## 为什么值得关注

机器人 RL 的主要瓶颈往往在问题建模，而不是训练算法本身，这一步目前仍然高度依赖专家手工完成。这篇工作把“写 MDP”变成一条可检查、可局部修正的自动化流水线，部署时不需要 LLM，安全性和可控性更好。对需要频繁更换任务或机器人的工业场景来说，有望明显缩短开发周期。
