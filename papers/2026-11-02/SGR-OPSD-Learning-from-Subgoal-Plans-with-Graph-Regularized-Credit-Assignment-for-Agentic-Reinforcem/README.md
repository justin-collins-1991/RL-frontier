## 一句话概括

把 LLM 生成的子目标计划当作"特权信息"喂给教师模型，给多轮智能体的每一轮动作打分，再用从 rollout 统计出来的"子目标进度图"校正这些分数，让 GRPO 的信用分配更贴近真实任务进展。

## 核心方法

- **子目标引导的教师**：只根据任务描述，让 DeepSeek-V3.1 生成一份固定的有序计划（如"找面包→放冰箱冷却→放到台面"）。教师看得到计划，学生看不到，两者对同一动作的对数概率差，就是"计划是否支持这个动作"的稠密信号。
- **有约束的加权**：把这个差值转成每一轮的有界权重，乘到 GRPO 优势上。权重不改变优势的正负，每条轨迹按 token 加权的平均权重固定为 1，相当于只在轨迹内部重新分配功劳，不额外放大或缩小整体更新。
- **子目标进度图校准**：把多条学生轨迹在相同状态处合并，统计每个动作之后的经验回报，和该状态的平均回报比较，得出"哪个动作更好"的偏好；再在不偏离教师权重太多的前提下，按这些偏好微调权重。教师偏好的是模型"觉得"好的动作，图提供的是实际交互中"真的"好的证据。
- 推理时计划和图都不需要。

## 关键结果

- 在 ALFWorld、WebShop、Search-QA 上，用 Qwen2.5-3B/7B，结果一致优于 GRPO 和多种自蒸馏基线。
- 7B 模型：ALFWorld 成功率 85.8%，WebShop 78.2%，分别比 GRPO 高 7.4 和 7.6 个百分点。
- 消融实验显示，子目标引导和图校准两部分都带来了明显增益。

## 为什么值得关注

OPSD 类方法的一个隐患是：教师的偏好不一定等于任务真的在推进。本文用"计划 + 经验回报"双重信号把稠密监督落到实处，而且只改优势权重、不改训练框架，几乎可以直接接到现有 GRPO 智能体训练流程里。对长链路、奖励稀疏的智能体 RL，这种低成本的轮次级信用分配思路值得借鉴。
