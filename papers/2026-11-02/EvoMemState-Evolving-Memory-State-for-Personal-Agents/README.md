## 一句话概括

个人 Agent 的长期记忆不能只存一条条孤立事实。EvoMemState 给每条事实补上"状态"：它现在是否还有效、和别的记忆有什么关系，以及在当前请求里该怎么用。

## 核心方法

- **本体引导的状态构建**：先从对话里抽出原子事实，挂到个人本体图上，再用"取代""冲突""包含"等关系把相关事实连起来，同时标注有效性和适用范围。旧记忆不删，只标成"历史"。
- **基于 RL 的状态演化**：训练一个策略模型（GRPO），针对每个请求生成"推理状态"，说明哪些记忆当前有效、各自起什么作用、优先级如何。奖励是冻结的 Agent 在有/无该状态时的回答得分之差，也就是按"带来了多少增益"打分。
- **状态感知推理**：把检索到的事实、关系状态和推理状态一起交给冻结的个人 Agent，由它生成回答。

## 关键结果

- 预实验发现：主流记忆系统有约 58%~62% 的情况没能把相关记忆检索全。即使检索全了，加上固定的自我反思提示，平均准确率反而从 50.5% 降到 48.9%。
- 在长期对话和记忆使用基准上，EvoMemState 的检索完整性和基于记忆的回答准确率都稳定超过 Mem0、A-MEM、LightMem、MemGPT 等基线。

## 为什么值得关注

论文点明了记忆系统里两个常被忽视的问题：一是"检索全了"不等于"用对了"，二是事实之间的更新和冲突关系必须显式维护。它把"怎么用记忆"交给 RL 从经验中学习，主模型保持冻结，只训练一个轻量策略，工程上容易接入现有 Agent。
