## 一句话概括

RLVR 训练里，难题常常长时间一次都做不对，然后突然被解出来，也就是"从零到一"的跳变。本文发现，这类即将突破的题目，失败回答里的不确定性更多集中在开头几个 token。基于这一点，作者提出 NAPO，给全错的组也提供有用的梯度。

## 核心方法

- **诊断**：用"首次做对所需步数"（TTFP）和 N→P（从全错变为有解）事件来追踪难题的学习过程。用固定 batch 训练，并从关键步重放训练做对比，发现之后能突破的题，失败 rollout 的前段熵明显更高，说明模型在开头还在"分岔探索"，并没有走进死胡同。
- **驱动指标**：取回答前 α 比例 token 的平均困惑度，除以整条回答的平均困惑度，得到"早期分岔比"，用它衡量一条失败回答离做对还有多远。
- **NAPO**：接在 GRPO 上使用。遇到全错的组时，按这个指标给组内的负样本排序，分配有梯度、不全相同的负优势值，并在组内归一化以保持训练稳定。这样，原本优势值全为零、没有学习信号的难题也能得到更新。

## 关键结果

- 在 rollout 预算相同的条件下，NAPO 让难题更早出现第一个正确解（TTFP 更低）。
- Pass@256 在 AIME24 上提升 10.0 分，在 AIME2025 上提升 6.6 分（基座模型为 Qwen2.5-Math-7B 系列）。

## 为什么值得关注

GRPO 在全错的组上没有梯度，这是 RLVR 在难题上停滞不前的老问题。本文没有靠增加采样或外部提示来解决，而是直接利用采样时已经有的 token 熵，区分"差一点就对"和"彻底走错"两类失败，几乎不增加额外成本，也容易接入现有的 GRPO 训练框架。它还说明从零到一的跳变可以被诊断、也可以被引导。代码已开源。
