## 一句话概括

不让 LLM 生成文字再解析成动作，而是给它一份带字母标签的可执行动作菜单，一次前向直接输出各选项的概率，再在这个"决策平面"上做 RL。

## 核心方法

- **问题**：token 级 RL 把动作的优势值分摊到整段回复上，包括推理、格式甚至乱码。同一个动作换一种说法，梯度就不一样，凭空多出方差；自回归生成还慢，输出解析失败就白白浪费一次交互。
- **做法**：编译器把观测、可选的紧凑记忆和带标签的动作菜单拼成输入，"大决策模型"（LDM）读取最后一个位置，在标签 token 上做 softmax，得到动作分布。只需一次 prefill，不生成文本，也不会出现非法动作。GRPO/GiGPO 等现有算法可以直接套用。
- **理论**：在同一个文本策略内，把同一动作的不同措辞合并起来，期望梯度不变，同时去掉一项零均值噪声（相当于 Rao–Blackwell 化）。
- **工程细节**：打乱菜单顺序，配合 KL 正则或校准项防止模型偏爱某个字母；按 episode 长度加权。
- **回迁**：用 LDM 的成功轨迹做 SFT，把策略蒸馏回能自由生成文本的 LLM。

## 关键结果

- ALFWorld：完整的训练+蒸馏流程用 12.7 H100 GPU 小时达到 99.3% 成功率；同一模型做 token RL 用 17.3 小时只到 86.6%。加上记忆后，Qwen2.5-1.5B 在可见和未见游戏上都达到 100%。
- ARC 上用约 1/10 的成本提升 2.6 个点；Countdown 提升 12~14 个点；Sokoban 44.5%，对照最高约 26%。
- 局限：换成零样本推理更强的 Qwen3.5-2B 时，token GRPO 在 ARC 上反超 1.8 个点。

## 为什么值得关注

对于动作空间有限的 agent 任务，这篇论文说明"让模型写出动作"并非必要：直接在动作上分配信用，方差更低、rollout 更省，也没有格式错误。"先在决策平面做 RL，再蒸馏回生成式模型"的流程，给 agent 后训练提供了一条更便宜、更稳定的路线。不足是它依赖可枚举的动作菜单，开放式生成任务用不上。
