## 一句话概括

BLPO 把不同任务里"进度相同、作用相同"的决策归为一组，跨任务、跨训练轮次累积经验来估计步级优势。它要解决的问题是：在长程 Agent RL 中，每个任务的 rollout 太少，做步级比较时样本不够。

## 核心方法

- **三路优势合并**：GRPO 式的轨迹级优势负责监督整体任务是否完成；局部优势在同一任务、同一观测下，先合并等价动作的回报再做比较；在此之上新增"任务进度优势"。
- **任务进度抽象**：用环境专属的预定义规则，把交互历史压缩成任务进度状态，把具体命令抽象成功能（如"拿取目标物品"）。这样不同任务、不同实体的对应决策就能共享统计量。
- **控制异构偏差**：先在具体上下文内对回报做中心化，以剥离任务难度差异；再均衡地写入随时间衰减的全局记忆，避免高频上下文主导估计；最后按样本支持度和不确定性加权，压低不可靠估计的影响。
- 不需要学习 critic，也不需要额外 rollout。

## 关键结果

在 ALFWorld 和 WebShop 上，1.5B 和 7B 策略在相同训练预算下的任务成功率都超过了所评测的基线，其中 1.5B 模型在 WebShop 上比 HGPO 高 2.48 个百分点。在同一套抽象下做的对照实验也支持跨任务共享确实有用。此外，ALFWorld 上学习更快，轨迹更短，额外计算开销很小。

## 为什么值得关注

GiGPO、HGPO 这类步级方法越追求历史一致，分到每组的样本就越少。BLPO 换了个思路：把信用估计从"单任务内比较"扩展成"跨任务的全局记忆"，几乎不增加成本，就缓解了样本稀疏问题。代价是要针对每个环境手写抽象规则，能否推广到开放环境还有待验证。
